## 2. 바뀌지 않는 것 (중요)

- **점수는 여전히 규칙 기반이야 (D2).** OCR은 질문 답을 채워주는 도우미고, 점수는 2번 API가 지금처럼 계산해
- **판독 못 한 건 `NO`로 채우지 않아.** 확인 못 한 질문은 사용자에게 묻는다
- **오늘 17시 목표는 그대로야.** 진단·일정표 2개가 먼저. OCR 때문에 오늘 기능이 흔들리면 안 돼
- API 1~4번 모양은 안 바뀌어. OCR은 **5번 API를 새로 추가**하는 거야

## 3. OCR은 이렇게 동작해 (docs/06 S2)

```
주소 입력 → 서류 첨부 (등기부 필수, 건축물대장 선택) → OCR (POST /api/ocr/registry)
   ├ 10개 다 확인 ─────────────────────────→ 금액 입력 → 진단
   ├ 일부 확인 못 함 → 그 질문만 직접 답하기 → 금액 입력 → 진단
   ├ 주소가 서류와 다름 → 주소 수정 또는 다시 첨부
   └ 전체 판독 실패 (422) → 다시 첨부 또는 10개 직접 답하기
```

| 상황 | 화면에서 |
| --- | --- |
| `CONFIRMED` 답 | 그대로 유지하고 **"서류에서 확인" 표시 + 근거 문장**을 보여준다. 원하면 고칠 수 있다 |
| `UNCONFIRMED` 답 | 그 질문만 순서대로 보여준다 (`질문 1/3`) |
| `A1_OWNER` 소유자 = 집주인 | 서버는 계약 상대방을 몰라서 보통 미확인. 등기부상 소유자 이름을 보여주고 사용자가 비교해서 답한다 |
| `R1_VIOLATION` 위반건축물 | 건축물대장을 안 올리면 미확인 |
| 근저당은 있는데 금액을 못 읽음 | 금액 입력 단계에서 **채권최고액만** 입력받는다 |

- **말소된 기록(빨간 줄) 문제**: OCR은 빨간 줄을 잘 구분 못 해. 그래서 등기부를 **"말소사항 미포함"(현재 유효사항만)으로 발급**하라고 안내한다 (인터넷등기소 발급 옵션, DG-16)
- **서류와 주소는 저장하지 않는다.** 응답·로그·DB에 소유자 이름을 남기지 않는다 (NFR-06)

## 5. OCR 엔진 후보 (BE2가 정하고 decision-log에 D9로)

| 후보 | 좋은 점 | 걸리는 점 |
| --- | --- | --- |
| AI 비전 API (Claude 등) | 서류에서 **질문 답까지 바로** 뽑을 수 있음. 표·빨간 줄 이해가 좋음 | API 키 필요, 서류를 외부로 보냄(NFR-06에 적기), 결과 확인 필요 |
| 클라우드 OCR (네이버 CLOVA OCR 등) | 한글 인식률 좋음 | 키·신청 필요, 글자만 나와서 답 판정은 규칙으로 따로 짜야 함 |
| Tesseract (무료, 로컬) | 키 없이, 서류가 밖으로 안 나감 | 한글 등기부 인식률이 낮음 → 데모가 불안함 |

어떤 엔진이든 **API 5번 응답 모양은 같다.** 엔진이 실패하면 422 `OCR_UNREADABLE`을 돌려주고, FE는 재첨부 또는 직접 답하기로 넘어간다.
