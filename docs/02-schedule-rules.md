# ③ 계약 일정표: D-day 규칙

> 상태: **초안 (팀 검토 전)**

## 입력

| 입력 | 필수 | 비고 |
|---|---|---|
| 계약일 | ✅ | 계약서 쓰고 계약금 보내는 날 |
| 잔금일 | ✅ | 나머지 보증금을 보내는 날 |
| 입주일 | 선택 | 비우면 잔금일과 같은 날로 처리 (보통 같은 날) |
| 계약 기간 | 선택 | 기본 2년. 만기 알림 계산용 |

## 규칙 표현 방식

할 일 하나 = **기준일(anchor) + 며칠 차이(offset)**. 예: "잔금일 당일 송금 전" = `BALANCE + 0`.
이렇게 하면 DB `checklist_items`에 `anchor`, `offset_days` 두 컬럼만 있으면 날짜가 계산돼.

| anchor | 뜻 |
|---|---|
| `CONTRACT` | 계약일 |
| `BALANCE` | 잔금일 |
| `MOVE_IN` | 입주일 |
| `EXPIRY` | 만기일 (입주일 + 계약 기간) |

## 연결 링크 (seed의 `link_name`, `link_url`)

할 일 하나에 링크는 하나만 넣는다. 서비스가 여러 개 적힌 줄은 **첫 번째 것**을 쓴다. 9·10·4~6처럼 비어 있으면 `null`.

|---|---|
| 인터넷등기소 | https://www.iros.go.kr |
| 정부24 | https://www.gov.kr |
| 국토부 실거래가 공개시스템 | https://rt.molit.go.kr |

> 확인 필요: URL은 QA가 한 번 눌러보고 확인하기.

## 화면 표시 규칙

- 오늘 기준으로 **지난 일 / 오늘 할 일 / 다가오는 일** 세 묶음으로 보여준다
- 9번과 11번은 놓치면 피해가 커서 **빨간 강조**
- 날짜가 겹치면 (예: 잔금일 = 입주일) 순서 번호대로 정렬

## Q&A 대비: "전세는 2년에 한 번인데 왜 다시 써요?"

13·14번이 답이야. 계약하고 끝이 아니라 **만기까지 이어지는 일정**이 있어서, 계약 후에도 다시 열어 볼 이유가 생겨.

> 확인 필요: 확정일자 즉시 발급, 대항력 다음 날 0시, 갱신 통지 기간(임대인 6~2개월 전, 임차인 2개월 전)은 일반적으로 알려진 내용이지만, 발표 전에 한 사람이 법령·공식 안내로 한 번 확인하자.
