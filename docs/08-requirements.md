- 저장소: https://github.com/LGCNS-HackerTon (BackEnd · FrontEnd)

## 1. 개요

| 항목 | 내용 |
| --- | --- |
| 목적 | 서비스가 제공할 기능과 지켜야 할 품질 기준을 한곳에 정의해 **개발·테스트·발표의 기준**으로 쓴다 |
| 한 줄 정의 | 사회초년생이 등기부등본을 옆에 두고 질문에 답하면, 위험 신호를 쉬운 말로 알려주고 중개사 질문·특약 문구·계약 일정표까지 안내한다 |
| 범위 | 기능 요구사항(4장) 34개, 비기능 요구사항(5장) 10개, 제약 사항(6장) |
| 근거 | docs/01 질문·점수, docs/02 일정, docs/03 API 명세, docs/04 DB, docs/06 화면 흐름, decision-log |
| ID 규칙 | DG 진단 · RS 결과 · SC 일정표 · AC 계정·기록 · UI 화면 공통 · AI 설명 생성 · NFR 비기능 |
| 우선 기준 | 문서끼리 다르면 **docs/03(API)·docs/01(점수)**가 이 명세서보다 우선한다. 이 명세서는 무엇을 만드는지, 03·01은 정확한 모양과 숫자를 정한다 |

| DG-04 | 모르겠어요 처리 | `UNKNOWN`은 **위험한 답으로 계산**하고 "중개사에게 확인하세요"를 보여준다 | P0 | 실제 | - |
| DG-05 | 채권최고액 입력 | 근저당권 질문(`B1_MORTGAGE`)에 `예`면 채권최고액 입력칸을 연다 (여러 개면 합계) | P0 | 실제 | - |

## 6. 제약 사항

| 항목 | 내용 |
| --- | --- |
| 법적 성격 | 사전 점검 도구일 뿐이다. 모든 전세사기를 막지 못하며 결과는 법적 판단이 아니다 (면책 문구 필수) |
| 입력 의존 | 등기부 내용과 시세는 사용자가 직접 입력한다. 잘못 입력하면 결과도 틀린다 |
| 시세 | 실거래가 자동 조회는 하지 않는다 (P2 / Next Steps). 빌라는 거래가 적어 시세가 부정확할 수 있다 |
| 계약 후 변동 | 등기부 변동 감시(알림)는 하지 않는다. 일정표로 "잔금 전 재확인"을 안내한다 |
| 계정 | 로그인·기록은 브라우저 저장 데모다. 서버 인증·DB 저장은 하지 않는다 |
| 범위 밖 | 등기부 사진 OCR, 실거래가 API, 서버 회원 관리, 배포 |
| 일정 | 개발 시간 약 6시간. 11/10 12:00 기능 동결, 이후 버그 수정만 |
