# Decision Log (결정 기록)

> 가이드 원칙 4 "Decisions Matter". 형식: **처음 생각 → 확인한 내용 → 바뀐 판단**. 발표의 "Key Decisions"와 개인 회고 재료가 된다.
> 결정할 때마다 한 줄씩 추가하자. 누가, 언제 정했는지도 적기.

| # | 날짜 | 주제 | 처음 생각 | 확인한 내용 | 바뀐 판단 / 결정 | 결정한 사람 |
|---|---|---|---|---|---|---|
| D1 | 11/9 | 아이템 방향 | 주소를 넣으면 위험도를 알려주는 "전세사기 위험도 계산기" | HUG 안심전세 앱 등이 이미 무료로 시세·위험도·악성 임대인 조회를 제공. 그런데 사회초년생은 앱을 모르거나 등기부를 읽지 못함 (팀 내 확인: ___명 중 ___명) | 계산이 아니라 **"이해하고 행동하게 돕는" 첫 전세 계약 가이드**. 기존 서비스로 이어주는 입문 도구 | 1팀 |
| D2 | 11/9 | AI 역할 | AI가 위험도를 판단 | AI 판단은 결과가 매번 달라질 수 있고 이유 설명이 어려움. 가이드상 AI 기능은 필수 아님 | **위험 점수는 규칙 기반**, AI는 쉬운 말 설명·질문·특약 문구만. 실패 시 템플릿 | 1팀 |
| D3 | 11/9 | 데이터 범위 | 테이블 7개 (회원, 매물, 실거래가 포함) | 개발 시간 약 6시간. 로그인·실거래가 수집은 핵심 흐름이 아님 | 테이블 4개로 축소. 시세는 직접 입력(Mock), 로그인·OCR은 Next Steps | 1팀 |
| D3-1 | 11/9 | 오늘 범위 | 메인 기능 3개 + AI를 이틀 동안 | 실제 개발 시간은 오늘 13~17시 4시간. ①등기부 읽기와 ②결과 안내는 사용자 입장에서 한 흐름 | **오늘 17시까지 기능 2개 완성**(등기부 진단, 계약 일정표). AI는 템플릿으로 두고 17시 이후/내일 | 팀장 |
| D3-2 | 11/9 | 로그인 범위 | 로그인은 범위 밖, 처음 FE 데모는 로그인해야 진단 가능 | 로그인을 강제하면 데모가 한 단계 늘고 "바로 써볼 수 있음"이 약해짐. 반대로 집을 여러 곳 비교하는 동안 기록이 남으면 반복 사용 이유가 생김 | **로그인은 선택.** 비로그인도 모든 기능 사용, 로그인하면 진단 기록을 마이페이지에 저장 (브라우저 저장 데모). 동·호수 입력은 문서에 없어 제외 | 팀장 |
| D3-3 | 11/9 | OCR 기반 진단 | 사용자가 서류를 읽고 질문 10개에 직접 답함 | 첨부 서류에서 확인할 수 있는 항목은 먼저 추출할 수 있음 | 주소·서류 첨부 후 OCR로 답을 채우고, 정보가 충분하면 금액 입력으로, 부족하면 미확인 질문만으로 이동한다. 점수는 기존 규칙으로 계산한다. 업로드 계약과 보관 정책은 별도 결정 (#10) | 1팀 |
| D4 | 11/9 | 기술 스택 | 새 기술도 고려 | 순수 개발 시간 4시간. 새 기술을 배우면 시간이 사라짐. 팀이 이미 배운 것 기준 | **Spring Boot 3 + JPA / React + Vite / MySQL 8**. 배포 없이 발표 노트북에서 로컬 실행 | 1팀 |
| D5 | 11/9 | 팀 이름·서비스 이름 | 후보: 도장 찍기 전에 / 전세 과외 / 첫 전세 / 집지킴이 | "안심"이 들어간 이름은 안심전세 앱과 헷갈림 (팀 회의 노션) | **팀명 "공감", 서비스명 "전세역전"** | 1팀 |
| D6 | 11/9 | OCR | OCR은 추후(Next Steps). 이후 D3-3에서 흐름 초안 | **강사님 피드백**: 등기부를 처음 보는 사용자가 직접 읽게 하면 사용성이 떨어진다 | **OCR은 무조건 적용** (흐름은 D3-3). 업로드 계약은 docs/03 5번, 서류는 **저장하지 않고** 응답·로그에 남기지 않는다. 점수는 그대로 규칙 기반 (D2) | 팀장 |

| D8 | 11/9 | 마이페이지 재평가 | 마이페이지는 기록 보기만 | 팀 회의: 로그인 회원은 조건을 고쳐 다시 평가해 보고 싶어 한다 | 로그인 회원은 마이페이지에서 **조건을 수정해 재평가(refresh)**. 우선순위 P1 (내일 12시 전) | 1팀 |
